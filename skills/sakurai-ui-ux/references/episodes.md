## J01 — Clarity vs. Style
*J: UI · 03:20 · [watch](https://www.youtube.com/watch?v=UjW_TTNtXEM)*

**Technique:** Aesthetic Style vs. Information Clarity Tradeoff — UI design exists on a spectrum between functional legibility and stylistic personality. Clear UI is not inherently superior to stylized UI; titles requiring high atmospheric immersion benefit from bold, expressive interfaces even if they introduce initial visual complexity, provided core navigation 
- ✅ Evaluate the tone, setting, and genre of the game before deciding whether to prioritize minimalist clarity or bold artistic expression.
- ✅ When employing aggressive visual styling (e.g., dynamic comic-book angles or heavy textures), anchor interactive commands directly to physical controller buttons to preserve operational speed.
- ✅ Assess whether an interface is hard to parse at a glance, and balance excessive decorative flourishes against the player's cognitive load in critical moments.
- ❌ Defaulting to sterile, generic list menus on the assumption that maximum readability is always the best user experience.
- ❌ Overloading screens with dense visual effects and skewed angles that obscure vital data without offering direct input mapping.
**Technique:** Drawer Metaphor for Information Density — Treat UI architecture like a physical chest of drawers sized to fit the volume of features and items in the game. Feature-dense titles require nested hierarchies ('drawers on top of drawers') or spatial organization so players are not overwhelmed by all available options at once.
- ✅ Categorize extensive game modes and settings into nested sub-menus to prevent the primary interface from becoming overcrowded.
- ✅ Provide clear organizational affordances (such as item frames, visual tags, or sub-folders) when players must manage massive quantities of inventory.
- ✅ Scale the complexity of the menu hierarchy directly to the volume of data; simple games should use shallow drawers, while complex games require layered organization.
- ❌ Dumping dozens of disparate gameplay systems onto a single flat menu layer without compartmentalization.
- ❌ Creating deep multi-layered sub-menus for games with minimal content, introducing unnecessary friction.
**Technique:** State Differentiation via Luminance and Saturation — Direct player attention across menu lists by applying deliberate contrast in brightness and color saturation between interactive states. Available tasks should pop with vibrant, saturated hues, while completed or inactive entries should recede into desaturated, low-contrast grays.
- ✅ Use high color saturation and brightness on active, selectable items to create immediate visual guidance.
- ✅ Desaturate completed or disabled list items into muted monochrome to drop their priority in the visual hierarchy.
- ✅ Ensure the contrast difference between active and inactive items is legible at a glance without requiring the player to read text labels.
- ❌ Displaying available and completed list items with identical background saturation, forcing players to read every entry sequentially.
- ❌ Highlighting disabled or cleared states with high-luminance colors that falsely draw player focus.
> In other words, clear UI doesn't always mean good UI, or vice-versa.
>
> Now, each menu has a number of key design points to consider.
>
> On top of that, try to make things more user-friendly where you can.

## J11 — Button Settings
*J: UI · 03:20 · [watch](https://www.youtube.com/watch?v=8nfMt4oG6hg)*

> I believe that every game, no matter how simple, should let you change button assignments through a key config.
>
> Many games set up their key configs as a vertical list, which is certainly easier to make-- but it can be difficult for players to keep track of which button does what.
>
> The key config screen is a menu in itself, so players need a button to let them exit it.
>
> If pressing that exit button instead starts the process of changing the button's assignment, you'll end up with a bit of a problem.
>
> It's always been that way in the rest of the world, but for us, it used to be the other way around.
